# 功能路線圖：讓任務很多的人愛上它

站在「每天事情很多」的使用者立場排出的優先順序。第一優先決定使用者會不會留下來，第二優先讓人愛上它，第三優先是加分項。

所有功能都遵守同一個原則：規則寫進 Markdown 任務行，不放在專屬資料庫。例如重複任務用 Obsidian Tasks 的 `🔁 every …` 格式，這樣資料換到別的工具也讀得懂。

## 第一優先：決定會不會留下來

| 功能 | 為什麼 | 狀態 |
| --- | --- | --- |
| 到期和時間提醒（Windows 通知） | 沒有提醒，使用者就不敢只靠它 | ✅ 0.7.0：開始前提醒、每日摘要；設定頁可以發一則測試通知 |
| 重複任務（每天、每週幾、每月幾號） | 很多事是固定週期的，不用每次重打 | ✅ 0.7.0 支援打字辨識；0.7.2 新增任務視窗加「重複」欄位；0.7.3 加「自訂…」，可設間隔、多個星期、每月幾號 |
| 任務內的勾選清單 | 拆成小步驟，又不用另開專案 | ✅ 0.7.0：卡片顯示完成進度（例如 2/5）；重複任務的下一筆會自動清空勾選 |

## 第二優先：讓人愛上它

| 功能 | 說明 | 狀態 |
| --- | --- | --- |
| 今天的負荷提醒 | 例如今天排了 9 小時，但可用時間只有 8 小時，就提醒排太滿 | ✅ 0.7.0：今天頁的負荷表，可用時數可以調整 |
| 「等待別人」清單 | 交辦出去的事集中在一起，時間到了提醒追進度 | ✅ 0.7.0：今天頁的等待清單，追蹤日一到就標示出來 |
| 每天結束的收尾 | 一鍵把沒做完的事移到明天，再看看今天完成了哪些 | ✅ 0.7.0：今天頁的「收工」 |
| 專注模式 | 一次只看一件事，做完或跳過再看下一件 | ✅ 0.7.0：今天頁的「專注」 |

## 第三優先：有更好

| 功能 | 說明 | 狀態 |
| --- | --- | --- |
| 任務完成的統計 | 這週完成幾件、哪個專案進展最多 | ✅ 0.7.4：今天頁的「回顧」，可以往回看 12 週 |

## 剩下兩項的前提

這兩項都需要雲端服務先把訊息收下來，因為使用者的電腦不一定開著。動手前要先確認：

- 架構與使用的服務
- 每月成本
- 學員資料怎麼保護
- 雲端必須維持可選：不用雲端的人，本機功能要照常完整可用

建議先做 LINE 轉任務。學員大多用 LINE，傳一句話就變成任務最直覺，也好拍成影片展示。手機記錄之後可以沿用同一套雲端服務。

## 手機與同步：方案討論（尚未決定）

> 這一節是討論紀錄，還沒有任何方案開工。目前公開發布的版本完全不連線到任何同步伺服器。

### 程式裡已經有的：早期的同步功能

早期為了連到自架的 Publisher 伺服器寫過一套同步，公開版本沒有開啟（打包時要另外設定伺服器網址）。它的做法：

1. **裝置配對**：每台電腦產生自己的私密金鑰，只存在本機；之後每個請求都簽名，伺服器認得是哪台裝置。
2. **只同步任務欄位**：標題、日期、狀態、所屬專案等。任務筆記內文、知識筆記、附件都不上傳。
3. **伺服器算合併計畫**：以「欄位」為單位合併，兩台裝置改不同欄位會自動合併，改到同一欄位才請使用者選。
4. **寫回 Markdown 才算完成**：先備份、再原子寫入，最後才回報伺服器；中途斷線可以重試，不會只改一半。

可以沿用的：裝置金鑰與簽名、欄位級合併、寫入日誌與重試。要補的：手機端、端對端加密、帳號與付費。

### 和 Google Drive 同步資料夾比較

| | Google Drive 同步資料夾 | 早期的同步功能 |
| --- | --- | --- |
| 同步單位 | 整個檔案 | 單一任務的單一欄位 |
| 兩邊都改了同一檔案 | 多出「待辦 (1).md」，要手動合併 | 不同欄位自動合併 |
| 手機新增任務 | 要在手機編輯 Markdown，不好用 | 可以做專用的輸入畫面 |
| 傳輸量 | 整個資料夾，含附件 | 只有任務資料，通常幾百 KB |
| 隱私 | 資料在 Google | 任務標題在我們的伺服器（可用加密解決） |
| 我們的成本 | 零 | 伺服器、維運、資料安全責任 |

### 參考：Anki 的模式

- 電腦版免費、開源；官方同步服務 AnkiWeb 免費。
- Android 版由社群開發、免費；iOS 版付費買斷，是主要收入之一。
- 給得起免費伺服器的原因：同步的資料很小（文字和複習紀錄），只傳變更，遇到合併不了就讓使用者選整份上傳或下載，維運成本很低。
- 也能自架同步伺服器，在意隱私的人不必用官方的。

我們的條件更好：只同步任務欄位，資料比 Anki 還小。

### 腦力激盪：可能的方案

**A. 加密收件匣中繼（最小可行）**
- 手機只做「新增」：輸入一句話，送到伺服器的暫存區；電腦開著時取走、寫進 `收件匣`，伺服器立刻刪除。
- 配對時電腦用 QR code 把公開金鑰交給手機。手機先用它加密再上傳，伺服器只看到亂碼，也只保存到電腦取走為止。
- 手機端用網頁（PWA，可加到主畫面、支援分享選單），不必上架商店。
- 同一個暫存區也能接 LINE 機器人、Email 轉寄，「從 LINE 轉成任務」可以一起完成。
- 缺點：手機看不到任務清單，只能新增。

**B. A 再加上「今天清單」唯讀快照**
- 電腦每次存檔，把今天和接下來幾天的任務加密後上傳一份快照，手機可以看、可以勾選完成；勾選也走 A 的暫存區回到電腦。
- 伺服器仍然只有加密資料。涵蓋大部分「出門在外」的需求，工程量比完整同步小很多。

**C. 完整雙向同步（Anki 模式）**
- 沿用早期同步，加上端對端加密：伺服器只存加密後的變更紀錄，合併改在使用者的裝置上做。
- 多台電腦、手機都能完整編輯。工程量最大，衝突處理要很小心。

**D. 電腦當伺服器（不存任何資料在雲端）**
- 手機透過中繼通道直接連到使用者自己的電腦，雲端只轉送、不儲存。
- 隱私最好，但電腦必須開著；家用網路與防火牆讓連線不穩，客服成本高。

**E. 只用使用者自己的雲端硬碟**
- 手機把任務寫成小檔案丟進使用者自己的 Google Drive 指定資料夾，電腦取走後刪除。
- 我們完全不碰資料、零伺服器成本；但要處理 OAuth 授權，延遲較長，各家雲端都要分別支援。

### 目前傾向

先做 **A**，再視需求做 **B**，**C** 等確定有人願意付費再說：

1. A 的工程量小、伺服器幾乎不存資料，最符合「不侵犯隱私」，也能順便完成 LINE 轉任務。
2. B 補上「出門看今天要做什麼」，大部分人到這裡就夠用。
3. C 是 Anki 等級的完整同步，留給真正需要多台裝置編輯的人。

不論做到哪一層，電腦版的本機功能都維持完整，雲端永遠是可選的。

### 速度目標

- **兩端都不等網路**：手機送出時先存在手機上、立刻顯示「已送出」，背景再上傳；電腦寫進 Markdown 也在背景完成。
- **用推送，不用輪詢**：電腦與伺服器保持一條長連線（WebSocket），手機一送出，電腦通常 1 秒內收到。
- **伺服器放在離使用者近的機房**（例如東京或新加坡），來回延遲約 30～80 毫秒。
- **只傳變更**：A 每則只有幾百位元組；B 的快照壓縮加密後通常幾十 KB。

### 動工前要決定

- 選哪個方案、先做到哪一層
- 加密與金鑰遺失時的處理（換手機、重灌電腦）
- 伺服器容量上限與未取走資料的保存期限

## 已知的小問題（低優先）

- 提醒固定用台灣時間（UTC+8）計算。
- 專注模式按「完成」時，不會等存檔完成才跳到下一件。
- 通知一直失敗時，只會安靜地重試，沒有提示使用者。
